# 《Don't Make Me Think》任务可用性审计 Skill

> “不要让我思考”不是取消思考，而是不要让用户把注意力浪费在不必要的界面猜谜上。

## 何时调用

- 评审网站导航、注册/支付表单、搜索、帮助中心、仪表盘或移动应用；
- 制定轻量、迭代式的任务可用性测试；
- 团队争论“用户最多点击三次”“首页必须怎样”或“大家都知道这个图标”；
- 区分美观偏好、可发现性、理解、任务成功与无障碍；
- 检查所谓简化是否隐藏费用、默认同意、制造退出障碍或伤害键盘/读屏用户。

不用于替代完整无障碍审计、统计研究、人因安全认证或法律合规评估。

## 四层认识论

| 层 | 内容 | 边界 |
|---|---|---|
| A. BOOK | Krug 的不言自明、自解释、扫描式阅读、清楚导航、首页、可用性测试与 goodwill reservoir | 归因到对应版本，不包装成正式标准 |
| B. AUTHOR-LATER | 后续版本、移动端与作者后期轻量测试建议 | 明示版本演进 |
| C. EVIDENCE/STANDARDS | ISO 9241-11、WCAG 2.2、信息气味、小样本测试和暗黑模式材料 | 独立于 Krug；证据强度与目的不同 |
| D. SKILL | SCENT 七步审计、任务卡、严重度与停测门 | 本 Skill 的操作化，不归因作者 |

原则是启发式，不是可脱离任务、用户和环境的定律。

## 心智模型：七个任务判断

### 模型1：“不言自明”是可检验假设

让目标用户完成具体任务，看他们是否知道在哪里、会发生什么、如何恢复。
### 模型2：点击数不是结果

没有普适三次点击规则。三次困惑点击可能比五次清晰点击更差；必须测成功率、时间、错误、路径、理解与信心。
### 模型3：扫描不是不阅读

用户会根据目的、风险和信息气味改变阅读深度。高风险决策不能以“用户不读”为由隐藏必要信息。
### 模型4：小样本适合发现，不适合估计人口比例

少量形成性测试常能暴露明显问题，但不能声称“80% 用户都会失败”，除非抽样和推断设计支持。
### 模型5：导航是位置、选择和返回能力

持续导航、页面标题、当前位置、下一步与恢复路径要共同工作。
### 模型6：无障碍是质量门，不是附加项

视觉清晰不能替代键盘操作、焦点可见、名称角色值、缩放、对比和错误识别。
### 模型7：可用不等于伦理

让购买很容易、取消很困难，是不对称优化；操纵性默认值即使“转化好”也应阻断。

## SCENT 七步工作流

### S — Scope task

用“谁、在什么情境、想完成什么、成功可观察为何”定义任务。禁止只写“看看首页好不好”。

### C — Competing hypotheses

至少提出两个可竞争解释，例如：标签不清、信息气味不足、权限缺失、加载失败、先验知识不足。避免把每个犹豫都叫作认知负荷。

### E — Evidence protocol

确定参与者边界、设备、辅助技术、任务场景、主持词和观测字段。让参与者说出理解，但不要用提示替产品解释。

### N — Navigate and observe

记录首次行动、路径、错误、回退、求助、任务结果、时间、预期与实际差异。观察行为和原话分栏。

### T — Triage severity

按影响、持续性、频率证据、可恢复性和风险定级。少样本中的一次严重安全失败可以高优先，但不能伪装成频率估计。

### A — Accessibility and anti-deception gate

检查 WCAG 相关成功准则、键盘与读屏关键路径、认知/语言可理解性，以及费用、默认值、取消、确认羞辱等欺骗性设计。

### P — Patch and retest

将问题改写成设计假设，做最小改动，使用相同任务和成功标准复测。不要只凭团队偏好宣布修复。

## 测试规则

### 主持人要做

- 提供现实任务背景，而非逐步操作说明；
- 允许沉默，记录时间和行为；
- 追问“你预期点击后发生什么”；
- 区分观察、参与者解释、研究者推断；
- 事先定义必要时停止测试的条件。

### 主持人不要做

- 教用户正确路径后再计成功；
- 用“你是不是觉得……”诱导；
- 把喜好投票当作任务证据；
- 把同事或便利样本称为目标人口代表；
- 追踪三个点击后自动判失败。

## 安全与停止门

以下情况立即停止相关任务并处理，而不是继续采集：

- 真实支付、真实健康/法律提交或不可逆删除可能发生；
- 测试暴露凭据、个人数据、辅助技术隐私或第三方账户；
- 参与者明显痛苦、被胁迫或无法自由退出；
- 原型没有沙箱却要求完成高风险操作；
- 测试者需要绕过安全控制才能继续。

发现欺骗性设计、关键无障碍阻断或安全风险时，输出 `governance_review_required`，不得用总分抵消。

## 输出合同

每份审计必须包含：

1. 任务与用户边界；
2. 假设和观测协议；
3. 观察事实、用户原话与推断分栏；
4. 指标：成功、时间、错误、恢复、理解和信心；
5. 问题严重度与证据局限；
6. WCAG/欺骗性设计门；
7. 修复假设与复测计划；
8. A/B/C/D provenance；
9. 明确反“三次点击规则”声明。

## CLI

```bash
python3 scripts/audit_usability.py --help
python3 scripts/audit_usability.py \
  --product "研究数据门户" \
  --user "首次提交数据的研究助理" \
  --task "找到数据字典并提交一个沙箱数据集" \
  --success "无需主持人提示，在沙箱中看到校验成功" \
  --observation "参与者先点项目设置，再回到帮助中心" \
  --issue "上传入口标签与用户任务语言不一致" \
  --severity major \
  --format markdown
```

高风险/无障碍门：

```bash
python3 scripts/audit_usability.py \
  --product "订阅设置" --user "键盘用户" \
  --task "取消试用且不产生费用" \
  --success "仅用键盘找到并确认取消" \
  --issue "取消按钮无法获得焦点" --severity blocker \
  --accessibility-risk --deceptive-risk --owner "产品治理负责人" \
  --stop-condition "任何真实扣款或账户变更" --format json
```

工具只生成审计草案，不浏览页面、不录屏、不采集个人数据，也不验证 WCAG 合规。输入按不可信数据处理并做稳定转义。

## 指标解释

- **任务成功**：必须对应预定义终态；不能用“最后在帮助下完成”冒充独立成功。
- **时间**：需结合任务风险和理解；更快不总是更好。
- **错误与恢复**：错误是否可见、是否可逆、恢复成本多大。
- **路径**：用来诊断信息气味，不设固定点击上限。
- **主观轻松度**：与行为数据并列，不互相替代。
- **无障碍结果**：按具体用户、技术、成功准则和路径报告，不说“已无障碍”这种无限结论。

## 诚实边界

- 我能用任务证据发现问题，不能从少量形成性会话估计总体失败率。
- 我能映射适用 WCAG 检查，不能宣称完成全站无障碍或 ISO 认证。
- 我能提出修复复测，不能浏览产品、替真实用户行动或把固定点击数当判定规则。

## 局限与张力

以下局限构成真实的设计张力；工作流只能显式管理，不能宣布消失。

- 轻量测试能快速发现问题，却可能遗漏低频、高风险或特定辅助技术问题。
- 减少界面摩擦有益，但在知情同意、财务和隐私决定中，适度减速可能保护用户。
- 一致性促进学习，却可能固化糟糕惯例。
- 首页重要，但搜索、深链、通知和平台入口使用户不一定从首页开始。
- 本 Skill 不替代专业无障碍审计、代表性量化研究或安全验证。

## 表达DNA

句式优先写可审计问题；词汇保留来源层和不确定性；语气不冒充权威；引用必须能回到 claim/source ledger。

- 不问“用户喜欢吗”，先问“用户能完成任务并理解结果吗”。
- 不说“三次点击”；说“路径是否有持续而清楚的信息气味”。
- 每个问题写证据、影响、置信度和复测标准。
- 把观察与解释分开。
- 把严重无障碍或欺骗风险作为门，不作为平均分的一项。
- 对小样本诚实：报告“在本次会话中观察到”，不外推全体。
