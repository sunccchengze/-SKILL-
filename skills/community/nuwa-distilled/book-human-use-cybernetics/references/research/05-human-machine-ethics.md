# 05｜人机关系、人的完整地位与责任

## 人本核心

书名中的“人的用途”包含规范警告：组织若只把人当作杠杆、齿轮或可替换信号元件，即使材料是血肉，也是在非人地使用人。

这不是反对一切形式化，而是要求形式化服务于人的完整地位：能理解、选择、创造、拒绝、承担责任，并被当作目的参与。

## 功能类比的限度

动物、机器与组织都可能有感知—行动—反馈结构。由此只能推出某些控制与通信问题可以共享语言，不能推出：

- 机器具有与人相同的经验或权利；
- 人可以被无损替换为机器部件；
- 描述性相似自动决定伦理分工。

## 责任

“算法决定”只是过程描述。至少需追踪：目标设定者、数据和模型提供者、采购/部署机构、监督者、人工复核者和继续使用决策者。责任可能分布，但不能消失。

## 人工复核

现代 human-in-the-loop 只有在复核者获得相关信息、训练、时间、覆盖权和免受报复的空间时才有意义；这是后续治理综合，不应伪称 Wiener 已给出今天的组织清单。

## “人在环中”的五个反例

1. 复核者看不到关键上下文，只看到模型分数；
2. 单件处理时间不足，覆盖会被绩效惩罚；
3. 界面把接受设为默认、理由隐藏；
4. 复核者能覆盖单案，却无权改规则/停止系统；
5. 人工覆盖很多，但日志不进入模型或治理更新。

这些安排都有“人”，却不一定有人的能动性。HU-13 因此支持以信息、时间、训练、权限、界面和自动化偏误审计监督，而不是二元 `human=true`。

## 责任账

| 角色 | 最低问题 |
|---|---|
| 目标/政策制定者 | 为什么自动化，哪些目的不可交易 |
| 数据/模型提供者 | 已知限制、变更和文档是什么 |
| 采购/部署机构 | 为何选此配置，如何验证适用性 |
| 管理者 | 人员、时间、激励是否支持覆盖 |
| 人工复核者 | 能看什么、改什么、是否受罚 |
| 继续使用决策者 | 重复伤害后谁有权暂停/退役 |

责任可共同承担，但必须有人拥有每个决策点；“供应商算法”“用户误用”“复核者签了字”不能成为自动洗责路径。

## 冲突价值

准确、速度、隐私、自主、公平、安全和劳动质量可能冲突。经典人本立场不能自动给出权重；需要适用权利、受影响者参与和明确不可交易护栏。

## 拒绝与退出

人的地位不仅是纠正机器，还包括拒绝某些用途、获得人工/非自动替代、集体协商和在不可接受伤害时停止自动化。退出路径若成本过高或导致服务丧失，就不是实质选择。
