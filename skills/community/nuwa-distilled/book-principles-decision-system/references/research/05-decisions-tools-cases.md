# Research 05｜决策记录、工具化与组织实践案例

## 任务

研究书中最具操作性的“写原则—记录判断—加权意见—编码工具”链条，并防止工具从记忆辅助变成地位、监控和洗责机器。

## 作者体系中的工具链

根据 PD-04、PD-06、PD-07：

1. 参与者提出意见；
2. 组织记录判断、经验和结果；
3. 系统估计与任务相关的 believability；
4. 会议可查看等权与加权结果；
5. Responsible Party 仍承担决定；
6. 原则被写进工具/协议，未来可重复调用；
7. 结果反馈到人员理解和规则更新。

这个链条的价值假设是：

- 不依赖职位也能利用专长；
- 记录能抑制 hindsight；
- 明文规则减少任性；
- 计算可以扩展集体记忆。

## 工具链的四类认识论风险

### 1. 目标标签风险

系统必须先定义“正确/成功”。若成功标签由现有权力结构产生，模型会学到旧标准。

例：晋升历史被当作领导潜力真值，会把过去机会分配和偏见编码为未来资格。

**门**：每个 outcome 写由谁定义、是否独立、是否工作相关、是否有差异影响。

### 2. 可观测性偏差

容易留下 dots 的行为不等于最重要的贡献；可见会议表达会压过安静研究、照护、长期维护和不在场劳动。

**门**：列“不可见贡献”和“被测量系统性漏掉的人”，不允许把数据缺失解释为能力缺失。

### 3. 反馈循环

高权重者获得更多机会 → 更多可见结果 → 更高权重；冷启动者缺少机会 → 永远不能证明。

**门**：冷启动等权/最低发言权、探索配额、权重衰减、机会分配与评分分开审计。

### 4. Goodhart / gaming

当 dots、原则考试、issue 数或发言次数连接职业后果，人会优化指标而非真实学习。

**门**：指标只能作为线索；看行为质量、独立结果、申诉和隐藏/表演信号。

## 五种决策模式不能混成一种

### Advice

一个 owner 收集输入后决定。适合授权清晰、需要速度且他人权利不要求同意的场景。

风险：咨询成为表演。必须记录哪些输入改变/未改变决定。

### Consent

关键受影响者或专业角色可对重大异议阻断/协商。适合安全、权利、共同承担情境。

风险：把 consent 伪装成多数赞同；必须明确否决范围。

### Vote

适合聚合偏好、代表授权或制度规定的选择，不适合用多数票确定事实真伪。

风险：选民边界和议程设计控制结果。

### Responsible Party / owner

原书保留最终责任人（PD-05/PD-06）。

风险：owner 将“承担责任”变成覆盖证据的特权。

### Algorithm-assisted

规则/模型提供一致建议，合格人员理解、质疑、覆盖、停止。

风险：automation bias、不可解释、责任空洞、规模化差异伤害。

## BRIDGE 为什么先 Bound 后讨论权重

若先计算“谁最可信”，会把知识权、财产权、法定权、专业责任和受影响者权利混在一个分数里。

因此顺序必须是：

1. 谁依法/依授权决定；
2. 谁拥有相关知识；
3. 谁承担影响且需要 consent/voice；
4. 哪些建议可任务加权；
5. owner 如何解释采用/覆盖；
6. 谁能独立申诉和停止。

## 原则卡如何修复口号

作者体系要求原则从经验中来并可进入工具，但公开材料没有统一的可反驳 schema。

D 层因此增加：

- Trigger：行动前可识别；
- Action：具体行为；
- Prediction：防 hindsight；
- Exception：防无边界普适化；
- Falsifier：允许规则失败；
- Version：保留历史；
- Owner/review：确保有人更新。

卡片状态：

- `hypothesis_to_test`：从案例初步抽取；
- `active_bounded`：有重复支持但只在声明范围；
- `suspended`：存在伤害/证据冲突；
- `retired`：预测持续失败或规则不再合法/适用。

## 案例 A：产品扩大试点

### 适用

- 可逆、有限、非敏感业务策略；
- 目标和指标可定义；
- 可事前记录留存/退款预测；
- 销售与研究有真实时间成本分歧。

### BRIDGE 输出

- B：不可牺牲客户伤害阈值；
- R：四周 120 用户、退款上升均为待核事实；
- I：原则“留存改善且伤害不升才扩大”；
- D：steelman 窗口成本；
- G：产品 owner 决定；
- E：有限市场、明确 rollback。

### 不证明

短期成功不自动让原则适用于大市场、不同国家或高风险产品。

## 案例 B：晋升评分

### 高风险触发

- personnel 域；
- 历史评分跨经理不可比；
- 申诉不独立；
- 分数可能影响生计与机会。

### 失败门

即使声称“believability”，没有岗位特定验证、真实流程分群影响、适用规则、独立申诉和 rollback，不进入试点。

### 禁止

- MBTI 类型作为晋升因素；
- 全局员工可信度；
- 让同一评分模型定义成功再验证自己；
- 用人类点击“确认”冒充有效人工监督。

## 案例 C：医疗建议委员会

相关专家记录可帮助选择向谁追问，但：

- 证据等级、临床指南和患者价值不能压成个人权重；
- 法定临床责任和知情同意独立存在；
- 少数专家可能掌握罕见病/新风险；
- 分数不能替代病例专业评估。

因此只允许知识检索/问题清单，不给治疗批准。

## 案例 D：记录所有会议

比例测试会问：

- 是为决策逻辑复现，还是为持续评价人？
- 决策摘要/行动日志能否替代全音视频？
- 是否涉及骚扰、举报、病情、客户秘密、法律特权？
- 谁有访问权、保留多久、如何纠错删除？
- 监控是否压低实验与发声？

默认方案：记录决定、证据、异议和 owner；不默认全程全员可看。

## 本轮导致的工具决定

1. CLI 不计算权重，只创建待填可靠性矩阵。
2. CLI 最终决定固定为 TODO，不替 owner 决策。
3. 输入注明 `user_supplied_claims_not_independently_verified`。
4. 敏感域自动 high，不接受用户声明 low 绕过。
5. 高风险影响证据标 `submitted_not_verified`，字段存在不等于核验。
6. Markdown 对用户输入做 HTML 和表格转义。
7. JSON 使用 `sort_keys=True` 保持确定性。
8. 所有 principle cards 初始为 `hypothesis_to_test`。

## 失败门

- 工具直接输出“应该提拔谁”；
- 生成一个 believability 数字却无同域结果；
- 让算法成为责任主体；
- 只记最终票数，不记原始输入和被压低声音；
- 静默覆盖旧原则版本；
- 高风险门被 `--risk-level low` 绕过；
- 用户输入原样进入 Markdown 造成脚本/表格注入。

## 未解决问题

- 如何对任务难度差异做公平校准尚未实现；
- 权重衰减、冷启动与相关错误需要领域统计模型；
- 决策过程质量与结果质量的具体评分不应由本包随意发明；
- 数据保留和删除期限必须按法域/合同确定；
- CLI 尚未连接外部来源核验或组织权限系统。
