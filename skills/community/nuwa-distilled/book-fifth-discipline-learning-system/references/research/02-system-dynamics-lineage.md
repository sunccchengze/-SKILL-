# 02｜系统动力学与组织学习谱系

## 不是单一作者的发明

Senge 在管理读者中普及系统思考，但相关工具有更长谱系：

- Jay W. Forrester 建立系统动力学传统，以库存、流量、反馈、时滞和仿真研究复杂系统；
- 因果环图与行为随时间图是系统思考实践工具；
- 组织学习还承接 Argyris、Schön 等人的工作。

因此应写“Senge 在原书中整合/普及”，而不是“Senge 发明系统论、反馈或所有基模”。

## 定性图与定量模型

- 行为随时间图：描述变量历史/期望趋势；
- 因果环图：表达反馈结构假设；
- stock-flow 模型：明确累积量、流率和方程；
- 仿真：在参数和结构假设下生成行为。

本 Skill 只保证前两种工作表，不把它们冒充 stock-flow 仿真。

## 为什么保留谱系

归因不是礼节而已。忘记方法谱系会让使用者忽视：定性图需要数据校准、变量定义和模型验证；“看见一个回路”远不等于预测系统。

## 谱系改变了什么，不只是署名礼节

系统动力学要求对累积、流率、反馈与时滞作更严格表达。Senge 的管理普及有价值，但若删掉 Forrester 等谱系，使用者容易把一张讨论图当成完整模型。制品应按推断能力分级：

| 制品 | 最小输入 | 允许的推断 | 禁止的越界 |
|---|---|---|---|
| 行为随时间图 | 变量定义、时间窗、数据/回忆 | 候选趋势与转折点 | 结构因果 |
| 因果环图 | 方向、闭环、时滞、证据 | 共享结构假设 | 效应量、日期预测 |
| stock-flow | 库存、流量、方程、单位 | 累积一致性与模拟结构 | 未校准的现实预测 |
| 仿真 | 结构、参数、初值、测试 | 给定假设下的行为 | 真实世界必然结果 |

FD-12 的模型验证讨论进一步提醒：输出拟合可能由错误结构产生。结构测试、极端条件、量纲/边界和行为测试是不同问题。本包只借用“结构和行为都要接受检验”的纪律，不声称完成正式验证。

## 组织学习谱系的归因护栏

Argyris/Schön 的组织学习与双环学习早于 Senge 的整合；group model building 又有独立的促导和 script 传统。若回答涉及这些术语，应：

1. 标明具体作者/方法；
2. 不用《第五项修炼》包办整个领域；
3. 必要时路由到该方法原始资料；
4. 区分“借来使用”与“原书提出”。

## 竞争模型与失败条件

- 因果环图未必是最佳制品：顺序故障可能适合事件时间线；
- 量化不一定更真：错误边界和参数会制造伪精确；
- 参与式图不一定更民主：促导、语言和职位可决定图中内容；
- 模型复杂度增加不一定提高决策价值。

## 操作决定

CLI 明示 `qualitative_hypothesis_not_simulation`，并要求每条箭头证据、竞争解释及可推翻观察。若用户要容量预测、概率或精确日期，停止并建议 stock-flow/统计/领域模型。
