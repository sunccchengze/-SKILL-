# Research Pass — 可解释性、正当程序与制度批评

## 目标

防止用 post-hoc explanation、model card 或技术 constraint 替代合法目的、申诉、人工权威与制度问责。

## 输入与方法

EA13 比较 interpretable model 与 black-box explanation，EA14 提供 model documentation，EA10/EA15/EA16 提供 abstraction/formalization critique，EA17/EA18 补治理/法律。

## 主要发现

解释须绑定 audience/task 并测 fidelity、stability、comprehension、actionability；不同角色需要不同答案。形式化会把文化语境、历史分类、组织资源与 lived harm 排除在 object 外。C-ETH-06 承载。

## 反证与边界

可解释模型仍可服务不正当目标；透明也可能带来隐私/安全冲突。human review 若无时间、authority、training 和 appeal 只是 rubber stamp。法规不可跨法域直接搬用。

## 设计决议

高风险决策要求 notice、real human review、appeal/correction、audit trail、remedy budget 与 stop。final status 最高 GOVERNANCE_REVIEW_REQUIRED。

## 纳入产物

本轮进入 `SKILL.md` 的 CONSTRAIN-ACT 步骤/停止门、`source-notes.md` 的来源卡、`claim-layer-map.md` 的对应 claim、`templates.md` 的强制字段，并至少由一个 adversarial test 或仓库集成断言约束。没有把研究日志当引用终点；最终输出仍须回链原始 source ID。

## 未解决

- 用户场景的本地数据、组织记录、受影响人证据和合法 authority 尚未知；不能由本轮桌面研究代填。
- 动态网页、软件、法律与在线书版本会变化；复用时重查基准日并记录差异。
- 形式字段可能被合规表演式填写；需要独立复核、反证、minority report 和可执行 stop/rollback。
