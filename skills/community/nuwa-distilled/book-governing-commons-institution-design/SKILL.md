# 《Governing the Commons》制度诊断 Skill

> **对象**：不是“社区自治很好”，而是诊断一群相互依赖者在特定资源、规则、信息、成本、权力和外部制度下，怎样可能形成可承诺、可监测、可争议、可修改的安排。

## 1. 何时使用 / 不使用

**使用于**：共享资源过取、维护不足、搭便车、规则不落地、共同体自治、合作社、灌溉/渔业/森林、开源/数据/算力生态的类比审查、多层监管和争端设计。

**不应单独用于**：
- 资源不具任何 CPR 式减损/拥挤/维护稀缺，却只因“共享”而贴 commons；
- 把“开放给所有人”当治理制度；
- 用八个 checkbox 代替参与式制宪；
- 以地方习惯压过基本权利、法律、弱势群体或外部受害者；
- 用自动监控/制裁替共同决策与 due process；
- 紧急生态/人身伤害时拖延保护。

## 3. 认识论与正当性合同

1. **resource ≠ property regime**：CPR 是资源结构；common property 是制度；open access 是规则缺失/无排他安排；public good 又有不同 rival/excludable 结构（GTC001）。
2. **模型有条件，不是命运**：Hardin/PD/Olson 在特定无沟通、无规则、无监测条件下有用；不是所有 field settings（GTC002）。
3. **国家/市场/自治不是三选一**：成功制度常是混合与嵌套，法院/国家可能承认与支持自治（GTC003–GTC004、GTC013–GTC014）。
4. **rules-in-use 优先**：成文 rule、实际 rule、例外、谁能改、谁执行必须分开（GTC006–GTC007）。
5. **八原则是 diagnostic association**：不是 blueprint、因果充分条件或排名量表（GTC018–GTC019）。
6. **durable ≠ just**：持续利用、生态结果、分配公平、尊严、合法性须分账；合作可能受精英/种姓/阶级强迫（GTC021–GTC022）。
7. **monitoring ≠ surveillance license**：监测者对谁负责、数据谁能纠正、监测资源还是人、制裁 due process 都要明写。
8. **digital transfer 要先证明结构**：信息可复制，物理 CPR 八原则不能原样搬；先找真正稀缺单位（维护、算力、注意力、生态/劳动成本）（GTC023）。
9. **诊断不是共同体同意**：CLI 状态 `institutional_diagnosis_not_governance_legitimacy`（GTC027–GTC028）。

## 4. 六个核心模型（三重验证）

### M1 CPR 两维结构：排除成本 × 减损性
- **跨案例**：牧场、森林、地下水、灌溉、渔场。
- **生成力**：先写 resource system、flow/stock、resource units、appropriation 与 provision。
- **排他性**：不因“公共价值”就叫 commons。
- **失败门**：找不到治理相关的减损/拥挤/维护约束，停止物理 CPR 类比。

### M2 action situation 与三层 rules-in-use
- **跨案例**：positions、actions、information、control、cost/benefit、outcomes；operational/collective-choice/constitutional。
- **生成力**：问谁可做什么、知道什么、承担什么、谁能改规则。
- **排他性**：从制度口号转向实际行动语法。
- **失败门**：正式 rule 与 field behavior 不一致时并列，不以政策文本覆盖实践。

### M3 contingent commitment 与互惠
- **跨案例**：参与者愿意遵守，条件是他人也遵守且违规可见/可处理。
- **生成力**：围绕 free-riding、commitment、institution supply、monitoring cost 写机制。
- **排他性**：不是假设人人利他，也不是只靠惩罚。
- **失败门**：制度让守规则者长期承担更高净成本且无纠正，承诺脆弱。

### M4 八设计原则是成组的机制线索
1. 资源与用户边界；2. appropriation/provision 与地方条件、收益/投入契合；3. 受影响者可改 operational rules；4. accountable monitoring；5. graduated sanctions；6. low-cost conflict resolution；7. external recognition；8. nested enterprises。
- **生成力**：每项写 evidence for/against、mechanism、failure、local adaptation。
- **排他性**：不打总分；缺项并不机械预测失败，存在也不充分。
- **失败门**：只复制原则名而无当地规则/结果证据，退回 M1/M2。

### M5 制度演化不是一次设计
- **跨案例**：试错、冲突、规则修改、监督信息和外部权威塑造长期安排。
- **生成力**：版本化 rule、触发 review、记录 conflict precedents 与退出。
- **排他性**：反对外部专家低成本“安装最优制度”。
- **失败门**：受规则影响者不能实质修改、申诉或退出，不能叫 collective choice。

### M6 嵌套/多中心治理处理尺度
- **跨层**：local units、watershed/region、state、cross-border；appropriation/provision/monitoring/enforcement 分层。
- **生成力**：每层标 authority、information、externality、appeal 与横向协调。
- **排他性**：polycentric 不是碎片化或无最终责任。
- **失败门**：某层成本外部化给无席位群体，须扩大 affected boundary。

| 模型 | 跨域 | 生成 | 排他 | 保留 |
|---|---|---|---|---|
| CPR structure | 自然/数字类比 | 定资源单位 | 非“共享”标签 | 是 |
| rules-in-use | 所有制度 | 行动语法 | 非政策文本 | 是 |
| commitment | 合作难题 | 激励/信任机制 | 非利他假设 | 是 |
| eight principles | 长期案例 | 证据/反证 | 非配方 | 是 |
| evolution | 长期治理 | rule versioning | 非一次设计 | 是 |
| nesting | 大尺度 | 跨层接口 | 非无协调分权 | 是 |

## 5. COMMONS 主工作流（D 层）

### C — Characterize resource
写 stock/flow、resource units、减损/拥挤、排除成本、再生/退化、基础设施、时滞、不确定性。数字场景分开 data content 与维护/compute/energy/labor。

### O — Outline boundaries
分别界定：resource boundary、authorized users、affected nonusers、providers、monitors、rights holders、external ecosystems。边界既防搭便车也可能排除弱者，必须写 inclusion/exclusion rationale 与 contest path。

### M — Map rules-in-use
每条 rule 用：
`[position] may/must/must-not [action] when [condition], with [information], under [control], producing [payoff/sanction]`。
标 operational / collective-choice / constitutional；标 formal / observed / disputed；谁能改，多久 review。

### M — Monitor reciprocity
分两类：resource condition monitoring 与 appropriator behavior monitoring。问：
- monitor 是否使用者或对其负责；
- 数据是否可见、可纠正、最小侵入；
- 监测成本谁付；
- monitor 自身谁审计；
- 自动化错误如何申诉。

### O — Organize collective choice
记录谁有席位、agenda/语言/时间/无障碍、反报复、quorum、minority objection、被规则影响者如何修改。参与人数不等于影响平等；写实际被采纳/覆盖轨迹。

### N — Navigate conflict and sanctions
建渐进 ladder：提醒/修复 → 比例后果 → 暂停 → 严重/重复升级；严重紧急伤害可直接保护，但必须有依据、通知、独立复核、恢复条件。conflict mechanism 要低成本、快速、当地可懂且可向独立层上诉。

### S — Scale by nesting
把 appropriation、provision、monitoring、enforcement、conflict、knowledge 各放合适层；设计 vertical feedback 与 horizontal coordination。scale jump 必须重新诊断，不把 100 人制度复制到全球。

## 6. 八原则证据卡

| 字段 | 必填 |
|---|---|
| local phenomenon | 哪个实际规则/行为对应？ |
| evidence for / against | 来源、时间、谁报告、缺席谁？ |
| mechanism | 如何改变信息/承诺/成本/信任？ |
| outcome | 生态、持续、分配、权利分别怎样？ |
| power | 谁定边界/数据/成功？ |
| adaptation | 不复制原案例，怎样契合当地？ |
| failure indicator | 什么会说明该设计无效/有害？ |
| owner/review | 谁能改、何时改、如何申诉？ |

## 7. 失败模式

| 失败 | 表现 | 修复 |
|---|---|---|
| open-access romance | “完全开放就是 commons” | 分清 property regime/rules |
| eight-box ritual | 八项全绿 | 每项证据/反证/机制/失败 |
| community essentialism | 假定偏好同质 | positions/power/history/exit |
| participation theater | 开会即共同决定 | agenda、影响、覆盖、反报复 |
| surveillance commons | 监控越多越可持续 | accountability、minimization、contest |
| sanction cliff | 无事/永久踢出 | graduated + due process |
| localism | 地方规则天然善 | rights/externalities/elite capture |
| durability laundering | 百年=正义 | 生态/分配/尊严/合法分账 |
| scale copy | 地方原则直接全球化 | science、nesting、cross-jurisdiction |
| digital analogy | data 像草场会耗尽 | 找真实稀缺 unit 与复制性 |
| polycentric fog | 多中心没人负责 | 每层 authority/interface/escalation |
| AI enforcement | 算法自动处罚 | collective choice + appeal + human owner |

## 8. 高影响门与 CLI

强制：`accountable-owner / applicable-rule / affected-group / legitimacy-evidence / appeal-path / rollback-trigger / stop-condition`。legitimacy evidence 是受影响者真实参与、影响与分群证据，不是模板自评。

```bash
python3 scripts/design_commons_governance.py \
  --resource "共享GPU集群" --resource-unit "每小时可调度GPU容量" \
  --boundary "三所研究机构共同采购的集群" \
  --user-group "研究团队" --user-group "平台运维" \
  --rule "高峰期每团队有基础配额，闲置配额可借用" \
  --monitor "由用户委员会问责的运维组" \
  --conflict-path "48小时内同行调解，之后独立委员会复核" \
  --domain digital --risk-level moderate --format markdown
```

CLI 不判断资源真的为 CPR，不分配配额，不代表共同体 consent。

## 9. 内在张力与边界

- **清晰边界 ↔ 不公排除**：边界支持投资回收，也可能封锁弱者/受影响非用户。
- **地方契合 ↔ 基本权利**：local knowledge 重要，但不正当习惯不因传统获豁免。
- **参与 ↔ 专业/时间成本**：实质 participation 需资源和便利，不把无暇参与者视为同意。
- **monitoring ↔ privacy/power**：可见性支持互惠，也可固化监控权。
- **graduation ↔ 严重伤害**：比例升级不是拖延即时保护。
- **autonomy ↔ external recognition**：自治需法律空间，也需处理跨界损害。
- **polycentric diversity ↔ coordination**：多样性提高适应，也增加冲突/重复/责任缝隙。
- **institutional durability ↔ transformation**：稳定可保护资源，也可锁定不公平权力。

本包不把 1990 自然资源案例写成 AI 预测，不声称八原则在用户场景中有因果效度，不替代产权、原住民权利、劳动、隐私、竞争、环境或行政法审查。
